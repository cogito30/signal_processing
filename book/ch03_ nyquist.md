# Chapter 03. 샘플링과 나이퀴스트 정리: 파동을 캡처하는 골든룰(Golden Rule)
- 앞선 장에서 우리는 세상의 물리적인 연속 신호(아날로그)를 컴퓨터가 이해할 수 있는 이산 신호(배열)로 가져오기 위해 **샘플링(Sampling)**을 거쳐야 한다는 것을 배웠습니다.

- 하지만 여기서 아주 중요한 질문이 하나 생깁니다.
- "도대체 1초에 몇 번이나 사진을 찍어야(샘플링해야) 원래의 신호를 잃어버리지 않고 완벽하게 담아낼 수 있을까요?"

- 데이터를 아끼겠다고 너무 듬성듬성 찍으면 원래 소리가 훼손될 것 같고, 무작정 촘촘하게 찍자니 컴퓨터 메모리가 터져버릴 것입니다.
- 이번 장에서는 이 딜레마를 해결해 주는 디지털 신호처리의 절대 법칙, 나이퀴스트-섀넌 샘플링 정리(Nyquist-Shannon Sampling Theorem)를 코드로 직접 증명해 보겠습니다.

## 1. 자동차 바퀴가 거꾸로 도는 이유(Aliasing)
- 액션 영화를 볼 때, 빠르게 달리는 자동차의 바퀴 휠이 어느 순간 뒤로 천천히 도는 것처럼 보이는 착시 현상을 경험한 적이 있나요? 이를 **마차 바퀴 현상(Wagon-wheel effect)**이라고 합니다.

- 이 현상은 카메라가 1초에 24장(24fps)의 사진을 찍고 있는데, 바퀴가 그보다 훨씬 빠른 속도로 회전하고 있기 때문에 발생합니다. 바퀴의 진짜 속도를 카메라의 '샘플링 속도'가 따라가지 못해 완전히 다른 가짜 움직임으로 왜곡되어 뇌에 전달되는 것이죠.

- 신호처리에서는 이렇게 원래의 고주파수(빠른 진동) 신호가 샘플링 속도 부족으로 인해 저주파수(느린 진동) 신호로 둔갑하는 끔찍한 왜곡 현상을 **앨리어싱(Aliasing)**이라고 부릅니다.

## 2. 코드로 체험하는 앨리어싱의 공포
- 백문이 불여일견입니다. 2장에서 만든 사인파 생성 코드를 이용해, 카메라(샘플링)가 빠른 파동을 놓쳤을 때 어떤 대참사가 일어나는지 파이썬으로 재현해 보겠습니다.

- 1초에 10번 진동하는 10Hz짜리 파동을, 1초에 고작 12번만 사진을 찍는 12Hz의 샘플링 레이트(Sampling Rate)로 캡처해 보겠습니다.

```python
import numpy as np
import matplotlib.pyplot as plt

# --------------------------------------------------------
# 1. 아날로그 원본 신호 (10Hz)
# --------------------------------------------------------
# 완벽한 아날로그 신호를 가정하기 위해 1초에 1000번(1000Hz) 촘촘하게 샘플링합니다.
t_analog = np.linspace(0, 1, 1000, endpoint=False)
signal_analog = np.sin(2 * np.pi * 10 * t_analog) # 10번 출렁임

# --------------------------------------------------------
# 2. 성능이 안 좋은 카메라로 샘플링 (12Hz)
# --------------------------------------------------------
# 1초에 12번만 점을 찍습니다. (fs = 12)
t_discrete = np.linspace(0, 1, 12, endpoint=False)
signal_discrete = np.sin(2 * np.pi * 10 * t_discrete) 

# --------------------------------------------------------
# 3. 앨리어싱 시각화
# --------------------------------------------------------
plt.figure(figsize=(10, 5))

# 원본 10Hz 신호를 흐리게 그립니다.
plt.plot(t_analog, signal_analog, color='lightgray', label='Original Analog (10Hz)')

# 12Hz로 캡처한 디지털 데이터를 빨간 점으로 찍습니다.
plt.plot(t_discrete, signal_discrete, 'ro', markersize=8, label='Sampled Points (fs=12Hz)')

# 캡처된 빨간 점들만 이어붙여 봅니다 (컴퓨터가 인식하는 최종 신호)
plt.plot(t_discrete, signal_discrete, 'r--', label='What Computer Sees (Fake 2Hz)')

plt.title("Aliasing Effect: Fast Wave looks like a Slow Wave!")
plt.xlabel("Time (seconds)")
plt.legend(loc='upper right')
plt.tight_layout()
plt.show()
```

(그래프 해석)
- 코드를 실행해 보면 놀라운 광경이 펼쳐집니다. 회색 선(원본)은 분명히 1초에 10번이나 오르락내리락하는 빠른 파동입니다. 하지만 빨간 점(우리가 캡처한 배열 데이터)들만 선으로 연결해 보면 어떨까요?

- 컴퓨터의 눈에는 이 신호가 1초에 단 2번 진동하는 아주 느린 파동(-2Hz)으로 보이게 됩니다!
- 원래 소리가 '삐이익-' 하는 고음이었다면, 샘플링을 잘못한 탓에 컴퓨터에는 '둥~ 둥~' 하는 엉뚱한 저음 배열이 저장되어 버린 것입니다.

## 3. 나이퀴스트 정리(Nyquist Theorem)
- 이런 앨리어싱을 막으려면 도대체 샘플링을 얼마나 빨리 해야 할까요?
- 이 질문에 해답을 준 수학자가 바로 해리 나이퀴스트(Harry Nyquist)입니다. 그의 정리는 아주 명쾌하고 강력합니다.

> "어떤 아날로그 신호를 완벽하게 디지털로 복원하려면, 신호가 가진 '가장 높은 주파수'보다 최소 2배 이상 빠른 속도로 샘플링해야 한다."

- 수식으로 쓰면 다음과 같습니다.

$$f_s > 2 \times f_{max}$$

- $f_s$ : 샘플링 주파수 (Sampling Rate)
- $f_{max}$ : 원본 신호에 포함된 가장 높은 주파수

- 왜 하필 2배일까요?
  - 파동의 형태를 최소한으로 인지하려면, 한 번의 진동(주기) 속에서 '가장 높은 산(산봉우리)'과 '가장 깊은 골(골짜기)', 최소 이 2개의 점은 사진으로 찍어두어야 파동이 위아래로 움직였다는 사실을 기록할 수 있기 때문입니다.


## 4. CD의 샘플링 레이트는 왜 44,100Hz일까?
- 이 정리를 현실 세계에 대입해 봅시다.
- 인간의 귀가 들을 수 있는 가장 높은 소리(가청 주파수)는 보통 20,000Hz (20kHz)입니다.

- 나이퀴스트 정리에 따르면, 인간이 들을 수 있는 세상의 모든 소리를 왜곡(Aliasing) 없이 디지털로 담아내려면 어떻게 해야 할까요?

$$f_s > 2 \times 20,000\text{Hz} = 40,000\text{Hz}$$

- 맞습니다. 최소 초당 40,000번은 샘플링을 해야 합니다.
- 우리가 즐겨 듣는 음악 CD(혹은 고음질 mp3)의 표준 샘플링 레이트가 44,100Hz(44.1kHz)로 정해진 이유가 바로 이 때문입니다. 여유 마진을 조금 더 두어, 44,100개의 배열 인덱스에 1초 치의 소리를 담아낸 것이죠.

## 5. 실제 오디오 파일(.wav) 읽어오기
- 이제 파이썬으로 진짜 소리를 담고 있는 .wav 파일을 읽어와 봅시다.
- 이 책에서는 필터링이나 변환 알고리즘은 모두 직접 짜지만, 오디오 파일을 열어서 배열로 꺼내오는 '파일 입출력' 작업만큼은 파이썬의 scipy.io.wavfile 패키지를 잠시 빌려 쓰겠습니다.

```python
from scipy.io import wavfile

# 실제 음성 파일 경로 (독자 제공용 파일)
file_path = "hello_world.wav" 

# wav 파일 읽기
# 반환값 1: sample_rate (이 파일이 1초에 몇 번 샘플링되었는가?)
# 반환값 2: audio_array (실제 소리 데이터가 담긴 1차원 넘파이 배열!)
sample_rate, audio_array = wavfile.read(file_path)

print(f"샘플링 레이트 (fs): {sample_rate} Hz")
print(f"배열의 크기: {audio_array.shape}")
print(f"이 오디오의 실제 길이: {len(audio_array) / sample_rate:.2f} 초")

# 앞부분 10개의 데이터만 슬쩍 확인해보기
print(f"데이터 샘플 (처음 10개): {audio_array[:10]}")
```

(결과 예시)
```
샘플링 레이트 (fs): 44100 Hz  
배열의 크기: (132300,)  
이 오디오의 실제 길이: 3.00 초  
데이터 샘플 (처음 10개): [ 0 12 -5 45 102 88 12 -20 -55 -40 ]  
```

- 파일을 읽어보니, 3초짜리 음성이 \[132300,\] 크기의 완벽한 1차원 넘파이 배열로 메모리에 올라왔습니다! 앞서 우리가 1, 2장에서 다뤘던 그 배열과 완전히 똑같은 형태입니다.

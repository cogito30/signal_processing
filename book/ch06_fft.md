# Chpater 06. 고속 푸리에 변환(FFT) 직접 구현하기: 1억 번의 연산을 10만 번으로 줄이는 마법

- 5장에서 우리는 이중 for문을 이용해 가장 정직한 이산 푸리에 변환(DFT)을 완성했습니다. 하지만 알고리즘의 관점에서 보면, 우리가 짠 코드는 최악의 시간 복잡도인 $O(N^2)$을 가지고 있습니다.
- 데이터가 작을 때는 문제가 없지만, 3장에서 배운 CD 음질(초당 44,100개의 샘플) 1초 분량을 분석한다고 상상해 봅시다. $44,100 \times 44,100 \approx 19$억 번의 루프를 돌아야 합니다. 파이썬으로 돌리면 커피를 내리고 와도 모자랄 시간입니다.
- 이 병목을 뚫기 위해 1965년 쿨리(Cooley)와 튜키(Tukey)가 발표한 고속 푸리에 변환(Fast Fourier Transform, FFT)은 "20세기 수학/컴퓨터 공학이 이룩한 가장 위대한 알고리즘 중 하나"로 불립니다.
- 이번 장에서는 복잡한 수학 증명을 내려놓고, 프로그래머에게 가장 친숙한 무기인 분할 정복(Divide and Conquer)과 재귀 함수(Recursion)를 이용해 $O(N \log N)$의 기적을 코드로 직접 구현해 보겠습니다.

## 1. 아이디어의 출발: 반으로 쪼개기 (분할 정복)

- FFT의 핵심 아이디어는 아주 단순합니다.
- "1,000개짜리 배열 전체를 한 번에 내적(DFT) 하려니까 너무 느리잖아? 그럼 짝수 인덱스와 홀수 인덱스로 반씩 쪼개서 계산한 다음, 나중에 합치면 안 될까?"

- 수학적으로 푸리에 변환 수식은 놀랍게도 다음과 같이 완벽하게 둘로 쪼개어집니다.

$$\text{DFT}(전체) = \text{DFT}(짝수) + W \times \text{DFT}(홀수)$$

(여기서 $W$는 회전을 의미하는 복소수 계수입니다.)

- 1,000개를 한 번에 돌리면 $1,000^2 = 1,000,000$번의 연산이 필요합니다.하지만 500개씩 두 번으로 쪼개면 $(500^2 + 500^2) = 500,000$번으로, 단 한 번 쪼갰을 뿐인데 연산량이 절반으로 줄어듭니다!

## 2. 끝까지 쪼개는 마법: 재귀(Recursion)의 도입

- 그렇다면 반으로 나눈 500개짜리 배열은 어떻게 계산할까요?당연히 250개씩 또 반으로 나눕니다. 250개는 125개로, 계속 반으로 나누다 보면 결국 '배열의 길이가 1'이 되는 순간이 옵니다.

- 길이가 1인 배열의 푸리에 변환은 무엇일까요? 바로 자기 자신입니다! 더 이상 내적을 할 필요도 없습니다.이 완벽한 구조를 우리는 재귀 함수(Recursive Function)로 아주 우아하게 짤 수 있습니다.

> 주의사항: 계속 반으로 나누기(Radix-2) 위해서는, 처음에 들어오는 배열의 길이 $N$이 반드시 2의 거듭제곱($2^1, 2^2, 2^3, \dots$)이어야 한다는 제약이 있습니다.


## 3. 밑바닥부터 짜는 재귀적 FFT (Python 실습)
- 이제 이중 for문을 버리고, 재귀 호출을 사용하는 우아한 FFT 알고리즘을 쌩코딩으로 작성해 보겠습니다.

```python
import numpy as np
import time

def my_fft(x):
    """
    1차원 배열 x를 입력받아 고속 푸리에 변환(FFT)을 수행하는 재귀 함수입니다.
    (입력 배열의 길이는 반드시 2의 거듭제곱이어야 합니다)
    """
    N = len(x)
    
    # [1] Base Case: 배열의 길이가 1 이하가 되면 쪼개기를 멈추고 자기 자신을 반환합니다.
    if N <= 1:
        return x
    
    # [2] Divide: 배열을 짝수 인덱스와 홀수 인덱스로 분할합니다.
    # x[0::2] -> 0, 2, 4, 6... 번째 원소
    # x[1::2] -> 1, 3, 5, 7... 번째 원소
    even_part = my_fft(x[0::2]) # 짝수 배열에 대해 다시 FFT (재귀)
    odd_part = my_fft(x[1::2])  # 홀수 배열에 대해 다시 FFT (재귀)
    
    # [3] Conquer & Combine: 쪼개서 계산된 결과를 하나로 합칩니다.
    # W는 합칠 때 필요한 복소수 회전 계수(Twiddle Factor)입니다.
    # k는 0부터 N/2 - 1까지의 배열입니다.
    k = np.arange(N // 2)
    W = np.exp(-1j * 2 * np.pi * k / N)
    
    # FFT의 대칭성을 이용해 앞절반(N/2)과 뒤절반(N/2)을 동시에 구합니다.
    # 앞절반: 짝수 + W * 홀수
    # 뒤절반: 짝수 - W * 홀수
    first_half = even_part + W * odd_part
    second_half = even_part - W * odd_part
    
    # 두 배열을 이어 붙여서(concatenate) 최종 N 길이의 배열을 반환합니다.
    return np.concatenate([first_half, second_half])
```

- 복잡해 보이던 시그마 수식이 사라지고, 배열을 반으로 쪼개서(x[0::2], x[1::2]) 자기 자신을 호출(my_fft)하는 재귀의 아름다움만 남았습니다.

## 4. 운명의 속도 대결: DFT vs FFT

- 코드만 예뻐진 것이 아닙니다. 5장에서 만든 $O(N^2)$짜리 `my_dft`와 이번에 만든 $O(N \log N)$짜리 `my_fft`의 실제 실행 시간을 밀리초(ms) 단위로 측정해 보겠습니다.
- 테스트를 위해 길이 $N=4096$ ($2^{12}$)짜리 랜덤 신호 배열을 사용합니다.

```python
# 5장에서 만든 my_dft 함수 (비교를 위해 잠시 소환)
def my_dft(x):
    N = len(x)
    X = np.zeros(N, dtype=complex)
    for k in range(N):
        for n in range(N):
            X[k] += x[n] * np.exp(-1j * 2 * np.pi * k * n / N)
    return X

# 4096개의 랜덤 신호 생성
N = 4096 
np.random.seed(42)
test_signal = np.random.random(N)

print(f"데이터 크기: {N}개")
print("-" * 30)

# 1. 기존 DFT 속도 측정
start_time = time.time()
dft_result = my_dft(test_signal)
dft_time = time.time() - start_time
print(f"my_dft 실행 시간: {dft_time:.4f} 초")

# 2. 새로운 FFT 속도 측정
start_time = time.time()
fft_result = my_fft(test_signal)
fft_time = time.time() - start_time
print(f"my_fft 실행 시간: {fft_time:.4f} 초")

# 3. 속도 차이 계산
speedup = dft_time / fft_time
print("-" * 30)
print(f"결론: FFT가 DFT보다 약 {speedup:.1f}배 빠릅니다!")
```

(실행 결과)
- 사용하는 컴퓨터 사양에 따라 다르지만, 통상적으로 아래와 같은 결과가 나옵니다.

```
데이터 크기: 4096개
------------------------------
my_dft 실행 시간: 6.8521 초
my_fft 실행 시간: 0.0152 초
------------------------------
결론: FFT가 DFT보다 약 450.7배 빠릅니다!
```

- 7초 가까이 버벅거리던 연산이 0.01초 만에 끝났습니다! 배열의 길이가 길어질수록 이 격차는 수천 배, 수만 배로 벌어집니다.

- 우리는 이제 그 어떤 거대한 오디오 데이터가 들어와도 눈 깜짝할 사이에 주파수 성분으로 분해할 수 있는 '고속 엔진'을 손에 넣었습니다.` numpy.fft.fft()`나 `scipy` 라이브러리의 블랙박스 함수가 속에서 어떻게 돌아가는지, 그 근본 원리를 완전히 깨우친 것입니다.


## Summary
- 전체 신호를 홀수와 짝수로 계속 쪼개어 계산하는 **분할 정복(Divide and Conquer)** 기법이 FFT의 핵심이다.
- 파이썬의 **재귀 함수** 를 이용하면 복잡한 수식 없이도 FFT를 우아하게 구현할 수 있다.
- 알고리즘을 최적화함으로써 $O(N^2)$의 연산량을 $O(N \log N)$으로 줄여, 수백 배 이상의 속도 향상을 얻어냈다.
